### 1.2. Ý nghĩa tên trường

**Phan Văn Hớn** (còn gọi Phan Công Hớn, khoảng 1830–1886) là nông dân, thủ lĩnh **cuộc khởi nghĩa Mười Tám Thôn Vườn Trầu** chống Pháp (tháng 2/1885) tại vùng Bà Điểm – Hóc Môn, cùng với Nguyễn Văn Quá. Nội dung này dùng cho trang *Giới thiệu – Lịch sử tên trường*.

## 2. Bài toán & mục tiêu đồ án

**Bài toán:** Trường mới thành lập (2026), chưa có cổng thông tin điện tử, nhân sự quản trị còn ít, cơ sở vật chất đang hoàn thiện ⇒ cần một hệ thống:
1. Làm **cổng thông tin chính thức** (giới thiệu, tin tức, thông báo, tuyển sinh, liên hệ).
2. **Quản trị nội dung & công việc nội bộ** (bài viết, lịch, hạn chót công việc).
3. Có **AI Agent** giúp ban giám hiệu / quản trị viên **điều khiển hệ thống từ điện thoại qua Telegram**: kiểm tra hệ thống, nhắc hạn, tự đăng bài khi đến hạn, thực thi thao tác trong phạm vi được phân quyền.

## 4. Yêu cầu chức năng

### 4.1. Phân hệ Website (Public)
- F01 Trang chủ: banner, tin nổi bật, thông báo mới.
- F02 Giới thiệu: lịch sử thành lập, ý nghĩa tên trường, BGH, tổ chuyên môn, cơ sở vật chất.
- F03 Tin tức – sự kiện, phân loại theo chuyên mục, tìm kiếm.
- F04 Thông báo (học sinh, phụ huynh, tuyển sinh).
- F05 Tuyển sinh lớp 10: chỉ tiêu, điểm chuẩn qua các năm, hồ sơ.
- F06 Thư viện ảnh / video, văn bản – biểu mẫu tải về.
- F07 Liên hệ, bản đồ.

### 4.2. Phân hệ Quản trị (CMS)
- F10 Đăng nhập, quên mật khẩu, đổi mật khẩu.
- F11 Quản lý người dùng & **phân quyền RBAC** (vai trò – quyền).
- F12 Quản lý bài viết: nháp → chờ duyệt → đã duyệt → **hẹn giờ đăng** → đã đăng → lưu trữ.
- F13 Quản lý chuyên mục, thẻ, media.
- F14 Quản lý **công việc & hạn chót** (task, người phụ trách, deadline, trạng thái).
- F15 Lịch sự kiện nhà trường.
- F16 Nhật ký hoạt động (audit log) – ghi mọi thao tác, kể cả của AI Agent.
- F17 Cấu hình hệ thống.

### 4.3. Phân hệ AI Agent + Telegram
- A01 **Liên kết tài khoản Telegram** với tài khoản hệ thống (mã OTP một lần sinh trong CMS → gửi cho bot). Chỉ Telegram ID đã liên kết mới được ra lệnh.
- A02 **Chat ngôn ngữ tự nhiên** tiếng Việt: “Hôm nay có bài nào đến hạn đăng không?”, “Đăng bài khai giảng lúc 7h sáng mai”.
- A03 **Kiểm tra hệ thống** (`/status`): tình trạng web, DB, hàng đợi, dung lượng, lỗi gần nhất, số bài chờ duyệt.
- A04 **Kiểm tra hạn chót** (`/deadline`): công việc sắp đến hạn / quá hạn theo người dùng hoặc toàn trường.
- A05 **Tự động đăng bài khi đến hạn**: Scheduler đăng bài đã duyệt đúng giờ, rồi báo kết quả qua Telegram.
- A06 **Nhắc hạn chủ động**: gửi tin nhắn trước hạn X giờ, báo quá hạn.
- A07 Thực thi tác vụ: tạo nháp bài, lên lịch/hoãn lịch đăng, đổi trạng thái task, tạo thông báo, tóm tắt báo cáo ngày/tuần.
- A08 **Xác nhận 2 bước** cho thao tác có ảnh hưởng (đăng công khai, gỡ bài): bot gửi nút *Xác nhận / Huỷ*.
- A09 Báo cáo định kỳ (ví dụ 7h sáng): việc trong ngày, bài sẽ đăng, cảnh báo hệ thống.

## 5. Mô hình phân quyền cho AI Agent (trọng tâm)

**Nguyên tắc:** Agent **không có quyền riêng**. Mỗi lệnh = (người dùng đã liên kết) × (quyền của vai trò) × (danh sách công cụ cho phép của agent). Agent chỉ làm được giao của 3 tập này.

| Nhóm thao tác | Admin | BGH | Editor | Giáo viên | Agent được phép? |
|---|:-:|:-:|:-:|:-:|---|
| Xem trạng thái hệ thống | ✔ | ✔ | – | – | ✔ |
| Xem hạn chót | ✔ | ✔ | ✔ | ✔ (của mình) | ✔ |
| Tạo nháp bài | ✔ | ✔ | ✔ | ✔ | ✔ |
| Duyệt bài | ✔ | ✔ | ✔ | – | ✔ (cần xác nhận) |
| Hẹn giờ / đăng bài | ✔ | ✔ | ✔ | – | ✔ (cần xác nhận) |
| Gỡ / ẩn bài | ✔ | ✔ | ✔ | – | ✔ (cần xác nhận) |
| Giao việc, đổi hạn | ✔ | ✔ | – | – | ✔ |
| **Xoá vĩnh viễn dữ liệu** | ✔ | – | – | – | ❌ **cấm** – chỉ trên web |
| **Quản lý người dùng / phân quyền** | ✔ | – | – | – | ❌ **cấm** |
| **Đổi cấu hình hệ thống, khoá bí mật** | ✔ | – | – | – | ❌ **cấm** |
| Xem dữ liệu cá nhân học sinh | theo quyền | | | | ❌ không trả qua Telegram |

**Biện pháp an toàn:**
- Agent gọi hệ thống **chỉ qua bộ công cụ (tools) định nghĩa sẵn**, mỗi tool kiểm tra quyền phía server — không để LLM tự quyết quyền.
- Nội dung bài viết/tin nhắn là **dữ liệu**, không phải lệnh (chống prompt injection).
- Ghi audit log: ai, qua kênh nào (web/telegram/scheduler), tool nào, tham số, kết quả.
- Giới hạn tần suất (rate limit), hết hạn phiên liên kết, có lệnh `/unlink`.
- Webhook Telegram có secret token; token bot và API key lưu biến môi trường.

## 6. Yêu cầu phi chức năng
- Bảo mật: HTTPS, băm mật khẩu (bcrypt/argon2), JWT + refresh token, RBAC, chống XSS/CSRF/SQLi.
- Hiệu năng: trang public < 2s; scheduler sai lệch đăng bài < 1 phút.
- Sẵn sàng: job hẹn giờ không mất khi khởi động lại (lưu trong DB/queue bền vững), có retry.
- Responsive trên điện thoại; hỗ trợ SEO cho tin tức.
- Dễ triển khai: Docker Compose.

## 7. Kiến trúc & công nghệ đề xuất

```
[Điện thoại - Telegram] ⇄ Telegram Bot API ⇄ (webhook) ⇄ ┐
                                                         ▼
[Trình duyệt] ⇄ Frontend Next.js ⇄ Backend API (NestJS) ⇄ PostgreSQL
                                      │   ├─ RBAC / Auth
                                      │   ├─ Module Bài viết, Task, Lịch
                                      │   ├─ Agent Service ⇄ LLM API (tool use)
                                      │   └─ Audit Log
                                      └─ Redis + BullMQ (Scheduler: đăng bài, nhắc hạn, báo cáo)
```

| Tầng | Đề xuất | Lý do |
|---|---|---|
| Frontend | Next.js (React) + Tailwind | SSR tốt cho SEO trang tin |
| Backend | NestJS (Node.js/TypeScript) | Có module, guard phân quyền, scheduler sẵn |
| CSDL | PostgreSQL + Prisma | Quan hệ rõ ràng, migration dễ |
| Hàng đợi / lập lịch | Redis + BullMQ | Job hẹn giờ bền vững, retry |
| Bot | Telegram Bot API (thư viện grammY/Telegraf) | Miễn phí, dễ dùng trên điện thoại |
| AI | LLM có hỗ trợ tool use (vd. Claude API) | Hiểu tiếng Việt, gọi công cụ có cấu trúc |
| Triển khai | Docker Compose + Nginx | Đơn giản cho đồ án |

*(Có thể đổi sang Python FastAPI / Laravel nếu nhóm quen hơn — kiến trúc giữ nguyên.)*

## 8. Ví dụ luồng nghiệp vụ chính

**Luồng: Tự đăng bài khi đến hạn**
1. Editor tạo bài → BGH duyệt → đặt `publish_at = 05/9 07:00`.
2. Hệ thống tạo job trong hàng đợi.
3. Đến giờ, Scheduler kiểm tra bài vẫn ở trạng thái *Đã duyệt* → chuyển *Đã đăng* → ghi audit log.
4. Agent gửi Telegram cho người tạo & BGH: “✅ Đã đăng bài *Lễ khai giảng 2026–2027*”.
5. Nếu lỗi → retry 3 lần → báo lỗi qua Telegram.

**Luồng: Ra lệnh từ Telegram**
1. BGH nhắn: “Dời bài khai giảng sang 8h”.
2. Bot xác thực Telegram ID → lấy user & vai trò.
3. Agent (LLM) chọn tool `reschedule_post` → server kiểm tra quyền.
4. Bot gửi nút xác nhận → người dùng bấm *Xác nhận* → thực thi → ghi log → phản hồi.
